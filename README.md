## 三分钟怎么玩

页面顶部四个入口：**帮我选 ｜ 选品攻略 ｜ 跟我换 ｜ 我的**

1. **发起一个投票**
   进「帮我选」→「发起投票」。可以填标题、加候选（2—8 个）、写价格、设参数，
   也可以在最上面输入一句话（例：`1500 左右的降噪耳机，通勤用`）点「起草候选」，
   会按品类和预算生成三个候选骨架，一键填进表单。

2. **投一票**
   打开任意投票，登录后点候选即可。登录用**邮箱 + 密码**，第一次用会自动注册，
   密码至少 6 位。换一台设备用同一个邮箱登录，看到的是同一份数据。

3. **把结论存成攻略**
   投票结束后在结果区点「存成攻略」，会生成"预算档位 / 关键参数 / 适用人群 / 避坑点"四区块。
   攻略进「选品攻略」，也进「知识库」（`#/kb`，攻略页顶部有切换）。

4. **看看判定怎么串起来**
   页脚有「链路演示」（`#/flow`）：起草候选 → 发起投票 → 计票 → 沉淀攻略 → 交换匹配，
   五步一条链路跑完，每一步的输入输出 JSON 都能展开看。

## 关于数据

投票与票存在云端（Supabase 托管数据库），**分享出去的链接在别人的设备上能打开、也能投**。
云端只存数据、只认账号，不做任何计算；计票、起草、攻略、匹配都在页面里的判定模块完成。

页面本身仍然是一份静态文件，离线时会退回本机数据继续用，只是别人看不到这一场。

「我的」页可以导出 / 导入全部数据（JSON）。想清空重来也在那里。

首次打开会自动生成演示种子数据（若干投票、攻略、交换单），方便直接看效果。

## 判定逻辑是怎么写的

四个判定模块各管一段，输入输出都是 JSON，不联网、不读数据库、不依赖页面状态：

| 模块 | 做什么 | 自检 |
| --- | --- | --- |
| `poll-result` | 计票、平票建议、信用门槛、到期判定 | 47 项 |
| `poll-designer` | 一句话解析品类与预算，起草候选骨架 | 29 项 |
| `guide-writer` | 投票结论 → 四区块攻略 | 19 项 |
| `swap-matcher` | 交换单按品类 / 价值 / 成色 / 新鲜度打分排序 | 23 项 |

网页本身是展示与表单层。打开页面时跑的是 `source/web/assets/js/pure/` 下同口径的 JS 版本，
Python 模块和这份 JS 镜像靠同一组用例锁住结果一致（合计 118 项）。
`PickForMe.html` 里也带着这份 JS，所以双击就能用，不需要装任何东西。

`#/flow` 页把四段判定串成一条链，逐步展示每一步的输入与输出 JSON。

源码都在可复现包 `PickForMe/source/` 里：

```
source/skills/   四个判定模块：源码、用例、自检脚本（纯 Python 3，无第三方依赖）
source/web/      完整前端源码（index.html + assets/css + assets/js）
```

跑自检（需要 Python 3.8 及以上，不依赖第三方库）：

```
python source/skills/poll-result/scripts/selftest.py
python source/skills/poll-designer/scripts/selftest.py
python source/skills/guide-writer/scripts/selftest.py
python source/skills/swap-matcher/scripts/selftest.py
```

四个脚本分别输出 47、29、19、23 项，全部通过即说明判定逻辑没被改坏。

## 已知限制（写在明处）

- 云端表目前是「匿名可读写」（演示期权限），没有防刷与防篡改；正式使用需切到按账号隔离的策略。
- 截止时间、轮次、信用分在浏览器里判定，改系统时间可以绕过——判定逻辑放在模块里、不放进数据库，是刻意为之。
- 私密投票的"仅链接可见"靠的是链接不可猜，没有权限校验。
- 站内消息只在本机投递（跨设备不同步）。
- 判定（计票 / 起草 / 攻略 / 匹配）全部由四个判定模块的浏览器镜像完成，数据库里没有任何计算逻辑。
- 交换只做撮合，不涉及支付与担保。
